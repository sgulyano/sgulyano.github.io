# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sarun Gulyanon's personal portfolio site, served by GitHub Pages from `master` at https://sgulyano.github.io/. It is a static site with no build system, no bundler, no tests, and no linter: pushing to `master` deploys. Preview locally by opening the HTML file or serving the repo root (e.g. `python -m http.server`) so relative paths and `fetch()` calls resolve.

## Layout

The repo root is the main resume page; each subdirectory is an independent, self-contained page or tool that shares nothing with the root page.

- `index.html` + `css/style.css` + `js/`: the resume. Bootstrap 4.5, jQuery 3.5, Font Awesome, and Academicons are all loaded from CDNs. Sections (`<section id="about|education|experience|publications|achievements|projects">`) are hand-written semantic HTML. The navbar links target these ids, and `js/index.js` smooth-scrolls to them with a 70px offset for the fixed navbar.
- Markup conventions: the HTML carries meaning, and the look lives in `css/style.css`, scoped per section. Bootstrap classes are kept for layout (`container`, `row`, `col-*`, spacing) and components (navbar, `list-group`, project cards). There are no inline `style` attributes. Headings run h1 (name) → h2 (section titles, `.section-title`) → h3 (entries).
- Experience is an `<ol class="timeline">`. Each job is an `<li>` with `<header><h3>Org</h3><time>Dates</time></header>`, then `<p class="role">` and an optional `<h4>Teaching</h4><ul class="courses">`. CSS draws the card, dot and connecting line (`::before`/`::after`), and `class="current"` highlights the present role.
- `fruitfly/`: a standalone interactive essay on the Drosophila connectome. It is a single `index.html` with inline CSS (design tokens on `:root`) and an inline `<script>`, using no frameworks.
- `tqf/`: a viewer for Thammasat University TQF3/TQF5 (มคอ.3/5) course documents. `tqf/index.html` fetches `<academic year>.json` (e.g. `2566.json`) when a year tab is clicked. Those JSON files are generated by the Python scripts (`requests`, `bs4`, `pandas`) in `tqf/run.bat`:
  ```
  python get_course_auto.py 3 tqf3.csv   # scrape TQF3 list from reg.tu.ac.th
  python get_course_auto.py 5 tqf5.csv   # scrape TQF5 list
  python get_data.py tqf3.csv tqf5.csv ./ # merge the last ~5 academic years (Buddhist Era) into <year>.json
  ```
- `eval/`, `moj/`: generated static HTML (course-evaluation snapshots, and a Folium/Leaflet map export). Treat these as artifacts, not source.
- `wd/`, `img/`: binary assets (images under `img/proj/` back the project cards).

## TypeScript → JS for the Projects section

The Projects cards are rendered at runtime by `js/project.js`, which `index.html` loads. That file is compiled from `js/project.ts`, where the `myproj` array holds the card data. To add or edit a project, change `project.ts` and then recompile so the committed `project.js` matches:

```
tsc js/project.ts   # emits js/project.js (default ES5-style output, as committed)
```

Card thumbnails live in `img/proj/thumbs/` as 960×540 JPEGs, generated by `python img/proj/thumbs/make_thumbs.py img/proj/thumbs`. Each one is a flat project colour with a figure, recoloured as a duotone and set on a paper card. The figure is either a crop of the project's original image from `img/proj/` (OJA, Raman) or a generated paper-style figure (sCT, Semanthai, microplastics). To add a project, add an entry to `PROJECTS` in that script (figure, label, palette). The originals are inputs only and are not referenced by the page.

Both files are committed; `js/package.json` and `js/node_modules/` are gitignored. `js/skill.ts`/`skill.js` work the same way but are currently unused: the Skills section and its `<script>` tag are commented out in `index.html`.
